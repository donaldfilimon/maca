Five catalogs. One binary. Nothing else to install.

The package manager that installs the others' packages.

One machine, several catalogs, one binary. maca installs from all of them without making you install a package manager for each one first.

One binary, five catalogs

Homebrew, winget, GitHub Releases, Aqua, and a local registry are HTTP APIs maca calls itself. The machine does not need brew, winget, gh, or aqua installed. Each of those tools covers its own catalog well; none of them covers the other four.

A failed install is reversible

Every mutating command snapshots the prefix first and rolls kegs, links, and the ledger back if it fails. Homebrew keeps old kegs but does not roll a failed multi-package install back. winget and aqua install forward. An exclusive prefix lock means two maca processes cannot race the cellar.

Checksums, and nothing foreign overwritten

Every artifact that declares a SHA-256 is verified before it is unpacked. An existing binary or man page that belongs to you, or to another package, is left in place and reported rather than replaced.

Declared, then verified

Groups, pins, and a lockfile name what should be installed. maca sync fails and rolls back if the version it gets is not the one the lock recorded. GitHub Releases and Aqua fetch that exact release; Homebrew and winget only publish their current version and refuse the request.

On the way

The gaps against the specialists are features in progress, not reasons to pick something else.

  • Pinned versions, fetched. GitHub Releases and Aqua fetch the release a lock or --version names. Homebrew and winget publish only their current version and refuse, so the wrong one is never installed quietly.
  • Per-directory versions. asdf and mise switch versions per project. A directory-scoped prefix over the same cellar is the planned shape, so switching reuses installs you already have.
  • The rest of Homebrew. Casks. Zip and tar casks install from the Homebrew cask API, checksummed, with the app left in the cellar rather than copied into /Applications. Disk images and installer packages are refused. Taps and services remain.
  • Hermetic builds. A source build inherits only its search path, locale, and temporary directory. Tokens and anything else in the caller's environment are dropped. A Nix sandbox is still the longer piece.
  • Windows installs. Catalog search, manifests, checksums, and dry-run plans run today. The installer launch path is written and waiting on a Windows host to be exercised.
Safety by design

Nothing gets lost. Nothing gets overwritten by accident.

Production-grade guarantees that work even when you run multiple commands at once or hit Ctrl-C mid-install.

Read the full safety model
Exclusive prefix lock

flock / LockFileEx on .maca.lock. Concurrent processes cannot race the ledger or cellar.

Automatic snapshots

Every mutation is preceded by a snapshot. Failure triggers full rollback — kegs, links, and ledger.

SHA-256 everywhere

Every downloadable artifact is verified before extraction. Custom entries without hashes are loudly warned.

No foreign overwrite

Existing binaries, man pages, or share files belonging to you or another package are left alone and reported.

Features that actually matter

Full TUI
Four-tab interactive terminal UI with search, filtering, pinning, upgrading, and snapshot management.
Groups & lockfiles
Declarative environments via maca group. Reproducible installs with maca lock / sync --prune.
Self-update
Fetches the latest GitHub release asset for your target triple, verifies the companion .sha256, and replaces itself atomically.
shellenv + completions
Portable shell integration for bash, zsh, fish, and csh. Tab completion for every supported shell via clap_complete.
Cache & disk hygiene
maca clean reclaims index caches, build logs, and temp trees. Snapshot pruning included.
maca doctor
Checks prefix writability, PATH, required dev tools, catalog endpoints, broken symlinks, and more — with structured exit codes.
